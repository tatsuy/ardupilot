# Copter-4.7.2 Loiter 近接センサ回避(屋内 SLAM 構成)の SITL 検証

対象: `Copter-4.7.2` (fb77356)。AVOID_ENABLE=3, PRX1_TYPE=2 (OBSTACLE_DISTANCE), AVOID_MARGIN=0.5, AVOID_BEHAVE=1 (Stop)。
目的: 「壁に近づくと 0.5 m 以内に入って止まらない」の再現と、変更1/変更2 の効果比較。

## 1. 検証環境

| 項目 | 内容 |
|---|---|
| 機体 | SITL `--model quad`、`--serial5=sim:vicon:`(autotest VisionPosition と同じ) |
| 位置源 | `VISO_TYPE=1, GPS1_TYPE=0, EK3_SRC1_POSXY/VELXY/POSZ/VELZ=6` (`prx_test/indoor.parm`) |
| 速度 | `LOIT_SPEED_MS=2.0`(屋内点検を想定)。その他は `Tools/autotest/default_params/copter.parm` 既定 |
| 壁 | home から北 7.0 m の無限平面。機体は点として扱う(AP 側と同じ) |
| センサ | `prx_test/wall_sim.py` が SIMSTATE の真値から 72 本(5°刻み)の測距を生成し OBSTACLE_DISTANCE を 15 Hz で送信。min_distance=0.2 m, max=12 m、遅延 0, ノイズ 0, FOV 360°, 欠落 0 で実施(いずれも引数で変更可)。0.2 m 未満の値はそのまま送り、AP 側で破棄される挙動を再現 |

各条件 2 回実施(PRX_FILT=1.0 のみ 1 回)。SITL はほぼ決定的で、2 回の差は数 cm 以内。

## 2. 仮説の検証

### 仮説1: 境界点の切り上げが時計回り側だけ — **コード上は正しい。ただし効果は限定的**

`AP_Proximity_Boundary_3D::update_boundary()` は sector 側の点(行 145-148)だけ 0.6 m に切り上げ、prev_sector 側(行 155-165)は切り上げない。
`AP_Proximity_MAV::handle_obstacle_distance_msg()` は面を角度の昇順(面 0→1→…→7)で `set_face_attributes()` するので、面 k の処理で切り上げられた点 [k] は、次の面 k+1 の処理で「prev 側の点」として切り上げなしで上書きされる。1 メッセージ処理後に切り上げが残るのは最後に処理される面 7 の点 [7] (−22.5°)だけで、正面の障害物線分 (点[7]–点[0]) は片端だけが 0.6 m に押し出された、傾いた線分になる。

ただし SITL では変更1(0.3 m に下げ、両側に適用)単独の効果は小さい:
T1 最小距離は変更なし、保持距離が 0.44→0.50 m 程度改善する程度(表参照)。0.6 m の切り上げは境界を実際より**遠く**に見せるので、0.5 m 以内に入ってからの後退(backup)の開始を遅らせる方向に働くが、食い込みの主因ではない。

### 仮説2: 加速度フィードフォワードが制限されない — **正しい。T2 (ホバリングからの入れ直し)の主因**

`AC_Loiter.cpp:382` の TODO どおり、`adjust_velocity()` は速度だけを制限し、`_desired_accel_ne_mss` はそのまま `set_pos_vel_accel_NE_m()` に渡る。
変更前で 2/3 スティックを 0.5 m の位置から入れ直すと、SA ログで `MVelX=0`(回避が速度を 0 にしている)にもかかわらず機体は 0.8 s で 0.7 m/s まで加速し、0.2 m 以内に入って突き抜けた(PRX_FILT=0 でも同じ)。1/3 スティックでも T2 の最小距離は 0.14 m。

変更2(回避が速度を削った方向の加速度 FF 成分を除去)で、T2 の最小距離は 2/3 スティックで「突き抜け」→0.28–0.42 m、変更1+2 では 0.44–0.50 m になり、揺れ幅 0 で静止する。

### 仮説3: PRX_FILT と近距離の欠落 — **正しい。T1 (走行中の接近)では PRX_FILT の遅れが支配的**

- PRX_FILT=0.25 Hz は 1 次 LPF (τ≈0.64 s)。1.2 m/s で接近すると境界点距離は真値より約 1.1 m 遅れ、回避が速度を削り始めた時点(境界 ≈1.7 m)で真の距離は約 0.3 m。4 バイナリのうち変更1+2 以外は壁を突き抜けた。PRX_FILT=0 にすると変更前でも T1 は 0.44–0.47 m で止まる。
- 0.2 m 以内に入ると正面の測距値が `min_distance` 未満になり AP で破棄 → 面が無効 → 境界点が 100 m に戻り、回避が外れて突き抜ける(CSV の `d_ap_front` が 12.0 になる瞬間と一致)。T2 の突き抜けはこの機構で完成する。

## 4. 読み取れること

1. **変更前の再現**: 1/3 スティックで T1 0.27 m、T2 0.14 m まで食い込み、保持は 0.43–0.44 m(0.5 m 未満)。2/3 スティックでは接近で突き抜ける(PRX_FILT 既定)。報告の症状は SITL で再現する。
2. **T1 (走行中の接近)** の食い込み/突き抜けは PRX_FILT=0.25 の遅れが主因。変更1・変更2 では防げない(変更1+2 だけが 0.10 m でぎりぎり止まったが、これは余裕があるとは言えない)。PRX_FILT を 0 または 1 Hz 以上にすると、変更前でも 1/3 で 0.44–0.49 m、2/3 で 0.36–0.47 m で止まる。
3. **T2 (ホバリングから入れ直し)** の食い込みは加速度 FF(仮説2)が主因で、PRX_FILT では直らない(2/3 で変更前・変更1 は PRX_FILT=0 でも突き抜け)。変更2 を入れると止まり、変更1+2 では 0.44–0.53 m で揺れ幅 0 で保持できる。変更1 は変更2 と組み合わせたときに最小距離を 0.28→0.47 m に引き上げる(境界が実際より遠くに見える分、後退が遅れるのを防ぐ)。
4. **変更2 の副作用**: T1 の保持で揺れ幅が 0.3–0.5 m のリミットサイクルになる(変更前は 0.44 m で静止)。変更前の静止は「FF で押し込み続ける力と Stop の釣り合い」で margin 内に沈んで止まる状態なので、FF を除去すると後退(backup)→再接近の繰り返しになる。AVOID_BACKUP_DZ を 0.1→0.05 にすると変更1+2 で 0.49 m・揺れ幅 0.01 m になった(1 回のみ)。AVOID_BACKUP_SPD を下げても改善しない。
5. 点検用途で「MARGIN=0.5 m で壁際に安定して保持」するには、(a) 変更1+2、(b) PRX_FILT の緩和(センサ側で既に平滑化されているなら 0〜1 Hz 程度)、(c) AVOID_BACKUP_DZ の縮小、を併用するのが本検証の範囲では最もよい。ただし (b)(c) は実機のセンサノイズで backup が暴れる可能性があるので、`wall_sim.py --noise/--delay/--dropout` で実機相当の条件を入れて確認してから決めるべき。
6. センサの `min_distance` 未満の破棄は「近づきすぎると回避が外れる」挙動になるので、実機では min_distance をできるだけ小さく申告する、または 0.2 m 以内に入らないよう margin を大きめにするのが安全側。

## 5. 制約・注意

- 壁は厚さ 0 の平面で、機体は点。突き抜けた後の数値は意味を持たない(表では「衝突」)。実機では衝突。
- センサは 2 次元・機体ピッチ無視(水平スキャン前提)。遅延・ノイズ・FOV・欠落はすべて 0 の「理想センサ」で実施した。実機では更に悪化する。
- sim:vicon の 25–125 ms の遅延は含まれる。SLAM 固有の遅延・ドリフトは入っていない。
- 変更2 の実装は「avoidance が削った速度ベクトルの方向」に沿う FF 成分だけを除去する最小限のもの(`prx_test/change2_loiter_accel_ff.patch`)。`_predicted_accel_ne_mss` は触っていない。upstream に出すなら Loiter 以外(PosHold など AC_Avoid を使う他モード)も同様に扱う必要がある。
- 変更1 は `PROXIMITY_BOUNDARY_DIST_MIN` を 0.3 m にするので、AVOID_MARGIN < 0.3 m の運用では境界が margin より遠く見える問題が残る。

## 6. 再現手順

```sh
cd ardupilot && git checkout Copter-4.7.2
./waf configure --board sitl && ./waf copter && cp build/sitl/bin/arducopter prx_test/arducopter_base
git apply prx_test/change1_boundary_min.patch  && ./waf copter && cp build/sitl/bin/arducopter prx_test/arducopter_c1
git apply prx_test/change2_loiter_accel_ff.patch && ./waf copter && cp build/sitl/bin/arducopter prx_test/arducopter_c12
git apply -R prx_test/change1_boundary_min.patch && ./waf copter && cp build/sitl/bin/arducopter prx_test/arducopter_c2
git apply -R prx_test/change2_loiter_accel_ff.patch

# 1 本だけ
python3 prx_test/wall_sim.py --binary prx_test/arducopter_base --outdir prx_test/out/x --stick-pwm 1333 \
    --param PRX_FILT=0.25 --delay 0.1 --noise 0.02 --fov 270 --dropout 0.05
# マトリクス(4 バイナリ × 2 スティック × 指定 PRX_FILT、3 並列)と表
python3 prx_test/run_matrix.py prx_test/out/m1 0.25 0
python3 prx_test/make_table.py prx_test/out/m1
```

ファイル: `prx_test/indoor.parm`(パラメータ), `prx_test/wall_sim.py`(壁センサ+テスト駆動), `prx_test/run_matrix.py`, `prx_test/make_table.py`, `prx_test/change1_boundary_min.patch`, `prx_test/change2_loiter_accel_ff.patch`, 結果 `prx_test/out/{m1,m2,rep2,extra}/*/{truth.csv,metrics.json,logs/}`。
